The duty board

One question, four jobs, four models — each on the work it is best at. Flip the keys you actually hold and the board reassigns itself, exactly the way the engine does.

1 · keys you hold

Every model that cannot be used is named on the board with the reason — never quietly missing. One key works; it just isn't fusion, and it says so.

3 · the rules the board just followed

Cover, never downgrade

Each job holds a chain of models, smartest first. Everything below the owner is cover — the next best model, never a cheaper one. There is no Haiku, no Luna, no mini or nano anywhere in the file. Every model runs at high reasoning effort, and one that refuses to says so rather than quietly answering at normal.

Two failures, two moves

Retired — renamed, or not on your account: the job moves down the chain, because asking the same model again could never work. Rate-limited: the same move, ending at the best open model Hugging Face will actually serve right then. A wrong key is neither, and stops the run with the real reason.

4 · the crew notebook

They learn from each other, not just from Fable 5

After every run one file is written, and every model — Fable included — reads all of it before writing a word next time. Rulings are binding. Crewmate notes are the crew's own track record.

RULING · high · name what you did not check
RULING · standard · a measured number, or say unverified
CREWMATE · claude-opus-5 as The Skeptic, scored 9/10 — strongest: named the failure nobody priced in · blind spot: no cost estimate
CREWMATE · gpt-5.6-sol as The Engineer, scored 6/10 — strongest: concrete mechanism · blind spot: ignored the rollout risk

Straight about what this is: it is memory, not training. The models themselves never change. What changes is that mistakes already caught, and moves that already worked, arrive attached to the next question. It lifts the floor of the work every run — not any one model's ceiling.
